## Pièges rencontrés (pour mémoire, en plus de ceux déjà documentés)

En plus des pièges déjà connus (no_proxy dans tmux réduit à `localhost`,
GROUP BY + OPTIONAL dans rdflib 7.6, croissance d'Oxigraph déjà suspectée,
erreur du Secret kubeconfig CAPI) :

1. **Scheme vide pour multicluster-runtime** : `mcmanager.New` ET le provider
   CAPI ont besoin d'un `runtime.Scheme` explicite (`clientgoscheme` +
   `capiv1beta2.AddToScheme`), sinon "no kind is registered for the type
   v1beta2.Cluster".
2. **Ordre de construction provider/manager** : le provider CAPI doit être
   construit AVANT `mcmanager.New` et lui être PASSÉ en argument (pas juste
   branché après via `SetupWithManager`), sinon "no multicluster provider set".
3. **Engagement par défaut de TOUS les GVK sur TOUS les clusters** :
   multicluster-runtime, dès qu'un provider est configuré, met
   `engageWithProviderClusters=true` PAR DÉFAUT pour chaque `Watches`/`For`
   d'un builder — y compris les GVK qui n'existent QUE sur le management
   (Cluster CAPI, Kustomization, HelmRelease, GitRepository, Machine). Il faut
   déclarer `WithEngageWithLocalCluster`/`WithEngageWithProviderClusters`
   EXPLICITEMENT par GVK.
4. **RBAC Secret namespacé mais cache cluster-scope** : `sylvatwin-reader`
   n'a les droits "secrets" que dans `sylvatwin-5gc` (pas cluster-wide),
   mais le `WatchesMetadata` par défaut du builder tente un LIST
   cluster-scope. Corrigé en restreignant le `cache.Options.ByObject` au
   namespace NF, uniquement côté workload.
5. **Durée de vie du contexte du Watch témoin** : passer le `ctx` du CYCLE
   (2 minutes, annulé à la fin) à `NewWitness` tue sa goroutine dès la fin du
   premier cycle — `lastWitnessRenewTime` se fige silencieusement et les
   verdicts basculent à tort en `UnknownVerdict` après ~30s. Il faut le
   contexte de VIE DU WATCHER (`New`/`Start`), stocké à part
   (`Watcher.longCtx`).
6. **Source `Live` recréée à chaque cycle** : casse la garantie P3 (le champ
   interne `last` d'une `*Live` neuve est toujours nil). Il faut UNE instance
   par cluster, réutilisée entre les cycles (`Watcher.sources`).
7. **Port metrics 8080 en conflit** : chaque instance de
   `sylvatwin-controller` ouvre par défaut un serveur de métriques sur
   `:8080`. Lancer deux instances en parallèle (ex. un test manuel pendant
   que l'opérateur permanent tourne) échoue avec "address already in use".
   Ajouté `--metrics-bind-address :0` (port libre choisi par l'OS) comme
   option.
8. **systemd --user n'hérite PAS du `no_proxy` enrichi du shell interactif** :
   le `no_proxy` qui inclut `172.30.0.0/24` etc. est défini dans `~/.bashrc`,
   pas dans `/etc/environment` (qui n'a que `localhost,127.0.0.1`). Le
   service systemd échouait avec "Proxy Authentication Required" sur les
   appels vers l'API CAPD. Corrigé en répétant les variables `http_proxy` /
   `https_proxy` / `no_proxy` explicitement dans le fichier `.service`
   (section `Environment=`).
9. **Deux Watcher dans le même process Go (tests envtest)** :
   controller-runtime refuse par défaut deux controllers de même nom dans
   son registre de métriques Prometheus global du process. Corrigé en
   activant `Controller.SkipNameValidation` à la fois sur le Manager ET sur
   le builder du controller trigger (le réglage du Manager n'est PAS hérité
   automatiquement par ce dernier). Sans conséquence en production (un seul
   Watcher par process H0).
10. **CRD exportés `kubectl get -o yaml` pour envtest** : contiennent des
    champs serveur (`status`, `metadata.resourceVersion`, `managedFields`) et
    une `conversion: strategy: Webhook` qui échoue sans webhook disponible.
    Il faut les nettoyer (retirer `status`, les métadonnées serveur, remplacer
    `conversion.strategy` par `None`) avant de les donner à
    `envtest.Environment.CRDDirectoryPaths`.
11. **Interférence entre deux contrôleurs pointant vers le même Oxigraph** :
    toujours utiliser une instance Oxigraph SÉPARÉE pour tout test manuel
    lancé en parallèle d'un contrôleur déjà actif (barrière 2h ou opérateur
    permanent), sous peine d'écritures concurrentes transitoires sur
    `GraphFacts`/`GraphDrifts`.
